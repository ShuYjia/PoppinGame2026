# ksm_death — ksm 死亡动画帧

由 `ksm_death/` 下 82 张 720×720 参考帧（AI 生成序列）制作的游戏用像素动画帧。
**配色以官方原生像素画 `D:/bang/nfc/ksm/12.png` 为权威来源**（21 色），不使用 AI 图自身提取的色板。

## 交付规格

| 项目 | 值 |
|---|---|
| 原生栅格 | **72 × 72**（源 720px ÷ 块宽 10px） |
| 帧单元格 | **84 × 84**（padding 6，与 `ksm_hurt_pixel` 一致） |
| 帧数 / 帧率 | **16 帧 @ 12fps**（约 1.33s，**一次性不循环**） |
| 枢轴 | **Bottom Center**（脚底中心） |
| 调色板 | **21 色，全部来自 12.png**，全序列统一 |
| alpha | 二值（0 / 255），**透明背景**，无抗锯齿半透明 |

## Unity 导入

- Sprite Mode = **Multiple**，Grid By Cell Size = **84 × 84**
- Filter Mode = **Point (no filter)**，Compression = **None**
- Pivot = **Bottom Center**
- PPU：与 `ksm_hurt_pixel` 取**同一 PPU**（两者原生格同为 10px/块）

## 处理管线（为什么这么做）

源图是 **AI 生成的"伪像素画"**：白底、约 2 万种颜色、带抗锯齿，并非真正的原生像素图。

### 1. 栅格判定
**块宽 = 10px**。用边界强度的周期检测（傅里叶相位聚集度 `power(N)`）确认，站立帧双向 power 达 0.55 / 0.42，是明确尖峰。

**但网格不固定**：倒地后 AI 让像素块跟随身体旋转重绘，轴向改变、相位逐帧漂移（1.55 → 6.71 → 9.30 → 0.65）。
→ 不能用固定网格逐帧采样还原，否则抖成噪点。

### 2. 处理顺序（关键）
- ❌ 先 1/10 面积平均降采样：采样窗跨多个原生块 → 颜色被平均糊掉（实测 705 格只剩 **3 色**）→ 再量化就成了纯剪影。
- ✅ **先在 720 分辨率上映射到官方 21 色**，再**众数降采样**（取窗口内出现最多的颜色，而非平均）。

### 3. 配色对齐（本次重点）
AI 源图整体比官方图**暗约 13.6%**（主色 (152,96,88) vs 官方 (170,110,102)），纯最近邻映射会让整片头发落到官方暗部色 (151,114,100)。

- ❌ 全局均值/标准差（Reinhard）迁移：会把 a/b 色度一并缩放，高饱和红被稀释（红色像素 2406 → 84、白色飙到 2600）
- ❌ RGB 逐通道线性比例（×1.13）：亮部溢出成纯白（白色占比 19.9%，官方仅 5.1%）
- ✅ **主导色配对 + Lab 明度平移**：两张图的最大频次色都对应同一部位（头发/皮肤），只平移 L 通道、保留色相与饱和度

### 4. 其他
- 水印「豆包AI生成」位于 `x 604–703 / y 676–697`，按 mask 精确抠除（不能用 82 帧中位数定位——其中 41 帧是静止躺姿会污染水印区；实测水印只出现在前 ~60 帧）
- 平坦化：删除过小的 alpha 连通域 + 孤立像素并入邻域众数（单轮、保守）

## 已知问题

- **源素材在 frame_058→059 处是硬切**——从"蜷缩"直接跳到"躺平"，中间过渡帧缺失。这是原始 AI 视频本身的不连续，不是抽帧造成。当前第 07→08 帧保留该跃变（dRGB≈87，其余相邻帧多在 2–50）。要更顺滑需手工补 1–2 帧。
- 后段（源 060–101）身体基本静止，只有上方元素在飘；已按配额压缩取样。

## 复跑

```bash
python ksm_death_pixel/make_ksm_death.py     # 生产
python ksm_death_pixel/qc_ksm_death.py       # 质检
python ksm_death_pixel/build_ksm_death_preview.py ksm_death_pixel   # 预览页
```

顶部 `CONFIG` 可调：`PALETTE_SRC`（配色的官方图）、`BLOCK`、`N_OUT`、`FPS`、`COLOR_MIGRATE`（0=纯最近邻，1=完全校正）、`ALPHA_CUT`。
